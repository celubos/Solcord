# Solcord 2.0.1

This release fixes startup and settings failures on modern Discord builds, restores Fake Deafen's visible state without disabling local audio, and addresses the 54-finding reliability and privacy audit.

## Install or update

On Windows x64, download **SolcordInstaller.exe** and **SHA256SUMS.txt**, verify the checksum, save drafts and leave calls, then open Setup and choose its recommended action. Existing settings, plugins, themes and private stores are preserved. **Refresh** detects a newly installed or updated Discord app. **Error details** shows a complete local error without uploading a report.

Open Discord **User Settings**, scroll to the bottom of the sidebar, and choose **Open Solcord Suite**. The Control Center opens independently of Discord's settings layout.

The Windows installer is unsigned. Use only the packages and checksums attached to this repository's release; do not disable Windows security.

## Privacy and reliability

- Strict Privacy retains native acknowledgement and optional telemetry, crash-reporting and activity protections. Essential Discord traffic still works. Updates remain manual.
- Editor/addon writes stay within owned folders, and redirected requests cannot forward credentials to a different host.
- Timeline saves larger batches correctly and retains privacy exclusions during partial message edits.
- Cancelled recordings and recycled attachment rows cannot reuse stale callbacks or download targets.
- Installer recovery preserves a usable startup path and checks shared-core ownership before changes.
- Fake Deafen confirms activation against the current call and transport, shows the user's deafened state, keeps local audio enabled, and restores normal behavior when switched off. The owner confirmed the repaired behavior.

## macOS preview

Apple Silicon and Intel users can opt into the separate **macOS command-line preview**. It stages an owned copy of Discord under the user's Applications folder and preserves the original application and profiles. It supports verification, repair, rollback, interrupted recovery and uninstall.

Mac packages must pass native fixture and packaging checks on both architectures. They are not Developer ID signed or notarized, and real Mac Discord startup, microphone, keychain and update acceptance remain unverified. Read the [Mac preview guide](../MACOS.md) before using them. No quarantine removal or Gatekeeper bypass is provided.

## Verification scope

The release workflow requires source tests, lint, types, documentation/inventory checks, Windows recovery and embedded installer tests, and both native Mac packaging jobs. Package manifests and `release-package.json` bind the downloads to the source commit. `RELEASE-SHA256SUMS.txt` covers all attachments except itself.

| Controlled check | Result |
| --- | --- |
| Backend soak | 30 minutes, 17,537 complete lifecycle cycles including Fake Deafen; 4.1 MiB post-GC heap growth; teardown checks passed |
| 1,000 sibling embeds in Chromium | Resolver median/p95 0.5/0.7 ms versus 24.2/27.8 ms in v2.0.0; containment calls reduced from 999,000 to zero per scan |
| Settings stress | 600 complete mounts/unmounts and 5,400 workspace transitions; zero remaining subscriptions or animation callbacks; no settings/privacy writes |
| Voice controller stress | 50,000 synthetic on/off cycles through the shipping controller, send-receipt helper and Patcher; zero remaining patches |
| Controlled Chromium UI | 43 scenarios passed |
| Windows installer UI | Normal and narrow layout, refresh, channel selection, busy feedback, recoverable errors and keyboard closing checked in disposable profiles; automated geometry checks cover 100–200% scaling |

Measurements use Bun 1.4.0 on Windows. Embed timings come from headless Chromium; settings timings use the production React tree in Happy DOM. They are not end-to-end Discord or call latency. [Machine-readable measurements and source hashes](2.0.1-performance.json) are also attached as **solcord-performance.json**. The release assembler rejects changed measured source files.

Synthetic tests do not establish a full live Discord network audit. Interactive rollback on the owner's Windows installation remains unverified; recovery fault tests use disposable targets. Mac previews require native compiled tests and copy/sign/verify/repair/rollback/uninstall checks against the current official Discord bundle without launching it.
