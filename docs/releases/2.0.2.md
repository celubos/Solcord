# Solcord 2.0.2

This release adds a discoverable **Message History** for deleted and edited messages, keeps Solcord manageable after Discord updates itself, and fixes Control Center controls that did nothing or misreported their result. Strict Privacy and the accepted Fake Deafen behavior are unchanged.

## Install or update

On Windows x64, download **SolcordInstaller.exe** and **SHA256SUMS.txt**, verify the checksum, save drafts and leave calls, then open Setup and choose its recommended action. If Discord is running, Setup now asks before closing it. Existing settings, plugins, themes and private stores are preserved.

The Windows installer is unsigned. Use only the packages and checksums attached to this repository's release; do not disable Windows security.

## Message History (deleted and edited messages)

- A new **Message History** workspace (search "deleted" or "edited") shows deleted messages, edited messages with every saved version, and ghost pings, with search, conversation filter, ordering, and **Open conversation**.
- Off by default. When turned on it saves DMs and group DMs, text only, for 7 days; server channels only when added one at a time. Your existing policy is preserved.
- Saved events stay on this computer, encrypted with AES-256-GCM under a key protected by the system's secure storage, or in memory only when that is unavailable or chosen. Names are resolved from Discord when you view the list and are not stored.
- Export and Erase each need a second confirmation. Turning it off does not erase anything; saved history keeps expiring while it is off.
- Fixes: a repeated message event no longer erases edit history or undeletes a message; retention is measured from first capture so a restart restores exactly what the session showed; saving no longer re-reads and decrypts all stored history; stored history stays within what a restart or export can read (newest 10,000 events per account), so export is never blocked by invisible residue.

[How Message History works](../MESSAGE_HISTORY.md).

## Discord updates

Discord installs each update in a new folder. Solcord now carries the installer's exact startup loader into that folder (or leaves it as ordinary Discord if it cannot finish), and the installer recognizes it. After a Discord update, Setup shows **Discord updated** and recommends **Repair** or **Update**. Previously, Update and Repair refused the updated folder, and Uninstall or a first-install Roll Back could remove the core while the newer Discord version still loaded it, which would stop Discord from starting; they now refuse first and explain. Loaders written by 2.0.1 are recognized.

The installer also cleans up a failed temporary write, no longer presents a completed install as needing Roll Back after an interrupted cleanup, removes leftover extraction folders from killed runs, and explains a removed recorded Discord version or channel.

## Control Center fixes

- Privacy Mode (screen-share redaction) has a real on/off switch; its options previously saved but had no effect.
- "Roll back latest setup" keeps working after many later edits; its snapshot is no longer evicted, and rollback checks it before touching files.
- Return Later **Open** navigates inside Discord instead of reloading it, which had erased the reminder list.
- Setup's Apply result and any failure stay visible after the wizard closes.
- Number fields save when you finish typing instead of clamping each keystroke.
- Failed exports, clears, removals and reminder actions now say so; "Check for updates" reports an unreachable source or available updates instead of always claiming success; voice indicator Hide/Show updates immediately; a stuck "Checking…" retry is fixed; Standard privacy means the same thing in Setup and the Privacy panel; link and file review switches stay reachable after Setup; buttons return keyboard focus after they finish; visible labels match screen-reader names.

## Verification scope

The release workflow requires source tests, lint, types, documentation/inventory checks, Windows recovery and embedded installer tests, and both native Mac packaging jobs. Package manifests and `release-package.json` bind the downloads to the source commit. `RELEASE-SHA256SUMS.txt` covers all attachments except itself.

| Controlled check | Result |
| --- | --- |
| Backend soak | 30 minutes, 17,622 complete lifecycle cycles including Fake Deafen; 4.1 MiB post-GC heap growth; zero failures; teardown checks passed |
| 1,000 sibling embeds in Chromium | Resolver median/p95 0.8/1.2 ms versus 32.5/38.9 ms for the v2.0.0 resolver on the same run; containment calls reduced from 999,000 to zero per scan |
| Settings stress | 600 complete mounts/unmounts and 6,000 workspace transitions including Message History; zero remaining subscriptions or animation callbacks; no settings/privacy writes |
| Voice controller stress | 50,000 synthetic on/off cycles through the shipping controller, send-receipt helper and Patcher; zero remaining patches |
| Controlled Chromium UI | 46 scenarios passed, including three Message History layouts (desktop, 320 px at 200%, 150% scale) |
| Message History storage | Encrypted-store tests cover 100/101/250-event batches across restarts, capacity at the readable bound, appends that never decrypt stored history, retention sweeps that create nothing, account isolation, corrupted keys, junctions, and clear/export completeness |
| Windows installer recovery | Install, update, rollback, 20 identical repairs, both channel orders, hard exits at seven uninstall points, canonical and 2.0.1-style Discord-update loaders, a removed recorded version, and leftover pending receipts |

Measurements use Bun 1.4.0 on Windows. Embed timings come from headless Chromium; settings timings use the production React tree in Happy DOM. They are not end-to-end Discord or call latency. [Machine-readable measurements and source hashes](2.0.2-performance.json) are also attached as **solcord-performance.json**. The release assembler rejects changed measured source files.

Not verified by this release's automated checks: signed-in Discord use of Message History with real deleted messages, real Discord self-update migration on the owner's PC, interactive Windows rollback on the owner's installation, and any real Mac startup, microphone, keychain or update behavior. Mac packages remain ad-hoc signed, non-notarized command-line previews.
